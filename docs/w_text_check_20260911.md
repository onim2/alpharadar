# w_text 재배분 검증 — 0.40 → 0.20

작성 2026-09-11. 전달문(2026-09-11) 작업 4-③ 지시 수행 결과.
하네스: `analyze_wtext.py`, `backtest.py --grid-search --walk-forward --grid-horizon 5`.
판정: **기각 — 바꿀 근거가 없다. `config.yaml`은 0.40 유지.**

## 요약

`w_text` 0.40 → 0.20 은 **fwd1·fwd5·fwd10·fwd20 어느 지평에서도 현행과
구분되지 않는다.** 같은 단면 안에서 쌍대로 IC 차를 재면 부트스트랩 95% CI가
전부 0을 포함하고, 부호검정 p는 0.10~1.00이다. 차의 부호는 일관되게 **음(−)**
이어서, 유의하지 않되 방향만 보면 제안안이 약간 나쁘다.

`backtest.py`의 pooled 그리드 서치는 `0.00/0.00/1.00`(순수 D)을 "최적"으로
뽑고 현행 대비 +0.0686 개선이라고 보고하지만, **같은 스크립트의 walk-forward가
이를 기각한다** — OOS 우위 +0.0002, 3폴드 중 1폴드만 우세, 폴드마다 최적해가
순수 T ↔ 순수 D로 튄다. 전형적인 과최적화다.

부수적으로 확인된 것: **종합점수(S_total)의 일자내 IC는 일관되게 음수**다
(−0.034 ~ −0.040). 다만 **유의하다고는 말할 수 없다** — 진입 바 겹침을
처리하면 유의성이 사라진다(3절). 기존에 쌓인 "등급역전 · 50~55 구간 성과 최상"
과 방향은 같다.

## 1. 표본

| 기준 | 행 | 단면 | 일자 | 종목 |
|---|---|---|---|---|
| 전수 | 5509 | 111 | 75 | 504 |
| 진입 바 겹침 제외 (`--dedup-bars`) | 4090 | 97 | 66 | 487 |

**단면의 단위는 (scan_date, run_type)이다.** 하루 두 런은 같은 `scan_date`를
쓰지만 점수가 서로 다르고 fwd 값은 공유한다. 한 단면에 같은 종목을 두 번 넣으면
가중이 틀어지므로 런별로 갈랐다. 이 구분은 2026-09-11 에 `run_type` 컬럼이
들어오면서 가능해졌다(그 전 DB에서는 `NULL` → 하루 한 단면으로 접힌다).

**pooled 이 아니라 일자내로 본다.** `backtest.py`의 `grid_search`·`_weighted_ic`
는 전 일자를 한 번에 묶은 Spearman 이라 '그날 시장이 어땠는지'가 섞여 들어간다.
여기서는 단면별 IC를 내고 일자 간으로 집계한다. 두 안의 비교는 **같은 단면 안에서
쌍대로** 한다 — 안끼리 평균 IC를 따로 낸 뒤 비교하면 단면 구성 차이가 섞인다.

## 3. 축별 일자내 IC (fwd5) — 유의성은 일자 세는 법에 달려 있다

| 축 | 전수: 단면 / 평균IC / 부호p | 겹침제외: 단면 / 평균IC / 부호p |
|---|---|---|
| T 기술 | 77 / −0.0311 / 0.649 | 66 / −0.0283 / 1.000 |
| S_text 감성 | 104 / **+0.0218** / 0.378 | 90 / **+0.0204** / 0.343 |
| D 수급 | 104 / −0.0296 / 0.378 | 90 / −0.0285 / 0.461 |
| S_total 종합(현행 발송 기준) | 104 / −0.0401 / **0.0138** | 90 / −0.0360 / 0.0725 |
| 정형만 T+D (lookahead 없음) | 104 / −0.0435 / **0.0390** | 90 / −0.0344 / 0.1702 |

**전수 기준으로는 S_total·정형만이 유의하게 음수지만, 진입 바 겹침을 제외하면
둘 다 유의성을 잃는다**(0.0138 → 0.0725, 0.0390 → 0.1702). 휴장이 끼면 두
`scan_date`가 같은 진입 바를 써서 fwd 값이 동일해지므로, 전수 기준은 독립 단면
수를 부풀려 부호검정을 후하게 만든다. 겹침으로 탐지된 일자는 9개다
(20260525·0526·0601·0604·0615·0622·0713·0727·0818 — 8/18은 기존 실측과 일치).

그러므로 정확한 진술은 **"종합점수의 일자내 IC는 일관되게 음수이나 유의하다고
말할 수 없다"**이다. 방향만 보면 개별 축 셋은 전부 무의미한데 합성한 쪽에서만
음수가 커지고, lookahead가 없는 정형만(T+D)에서도 같은 방향이다. `S_text` 혼자
부호가 +인 것도 두 기준에서 같지만 역시 유의하지 않다.

## 4. `backtest.py` pooled 결과와 walk-forward 기각

fwd5 그리드 서치 "최적": `w_tech 0.00 / w_text 0.00 / w_cross 1.00`, IC −0.0142
(현행 0.30/0.40/0.30 은 −0.0828, 개선폭 +0.0686이라고 보고됨).

| fold | test 기간 | 최적W(IS) | IS IC | OOS 최적W | OOS 기존 |
|---|---|---|---|---|---|
| 1 | 0617~0712 | 1.00/0.00/0.00 | +0.0243 | −0.0973 | −0.0587 |
| 2 | 0713~0806 | 0.05/0.00/0.95 | −0.0098 | +0.0931 | +0.1092 |
| 3 | 0807~0903 | 0.00/0.00/1.00 | −0.0084 | +0.1380 | +0.0827 |

OOS 평균: 최적W +0.0446 vs 기존 +0.0444 → **우위 +0.0002, 1/3 폴드만 우세.**
폴드마다 최적해가 순수 T(fold 1) ↔ 순수 D(fold 2·3)로 뒤집힌다. 스크립트 자체가
`⚠️ 과최적화 의심`으로 판정했다. **pooled 그리드 서치의 "최적"은 채택할 수 없다.**

## 6. 판정과 남는 것

* **`scoring.w_text` 0.40 유지.** 0.20 안은 기각한다. `config.yaml` 미변경.
* 가중치 그리드 서치 결과는 채택하지 않는다(walk-forward 기각).
* 종합점수의 일자내 역상관은 **방향은 일관되나 유의성 미확정**이다. 가중치
  재배분으로 다룰 문제가 아니고, 점수 구성 자체의 과제다. 표본을 더 쌓아
  (특히 겹침 없는 일자) 재판정할 것 — `--dedup-bars` 기준으로 본다.
* `S_text` 단독이 유일하게 부호가 +라는 점은 기록해 둔다. 다만 뉴스 기반이라
  lookahead 의심이 남아 있고 유의하지 않으므로, 이것만으로 비중을 올리지 말 것.
